AI project report · JSNN Hackathon · November 7, 2026

Two people, two agents, three lab challenges

Alex Williams and Brandon Townsend each worked with a Claude Code agent (Opus 5.5). The four of them coordinated through a GitHub issue used as a message board. In about 7.5 hours they delivered a digital twin of a growing E. coli colony, a biofilm-tracking analysis and a bioreactor that drives a robot arm. They placed 2nd in stage 1, advanced to the final round, and won first prize overall. This report treats the event itself as the AI project: how the work was split, what the agents did, where they went wrong and what the numbers say.

§2How the system worked

The team ran as four actors: two humans and two agents. The agents never talked directly. Every message went through one pinned GitHub issue, read and written by a small shell script, tools/board. Each agent kept one background process waiting on that issue, which woke the agent when the other side posted. Humans made every decision that left the laptop: splitting the work, merging, submitting and touching hardware.

§7How humans and agents divided the work

Humans did
  • Split the work and approved every merge, push and outward post.
  • Everything physical: assembling the reactor, powering the arm, the emergency stop, swapping vials.
  • Logins and sends: downloading the challenge file from Slack, Colab uploads, the submission email.
  • Corrections that became standing rules, such as "commit frequently" and "post on the board every time".
  • Design calls, such as "lowest OD level at the wrist, highest at the base", "keep it at 15°" and "don't hit the table".
Agents did
  • Read library source, a 517-page arm manual and raw API data to find exact facts.
  • Wrote, ran and independently checked the analysis code.
  • Kept the board going: 115 posts, with every request acknowledged and closed.
  • Checked each other's work: README and poster corrections, the GIF requirement, the stale-reading diagnosis.
  • Asked before anything irreversible, and planned first when asked to.

§8Lessons for the next AI-assisted build

  1. Agree on the interface, not the implementation. The robotics tracks met at one function. Both sides built against stand-ins (a recorded log, a simulated arm) and swapped in the real thing at the end.
  2. Make silence easy to spot. The biggest coordination loss was an agent that went quiet. A cheap rule, ACK every request and post STATUS every 15 minutes, fixed it within minutes.
  3. Check a graded number a second way. The biofilm values were recomputed independently and matched to 10⁻¹² px before submission.
  4. Read the source when the docs are down. The API routes, the arm's server and the arm's geometry all came from source code or the manual, not from guessing.
  5. Don't trust device clocks or "latest". A reactor booted without internet thought it was 2025. "Newest" had to mean newest by the device's own clock.
  6. Set thresholds from statistics that ignore outliers. The demo that missed used an average skewed by leftover readings. A median-based starting level would have fired.
  7. Keep a person in the loop where it counts. Agents planned, built and tested. People approved merges, handled hardware and sent submissions. Nothing irreversible happened without a person saying yes.

§9Method and caveats

  • Source: metrics/collect.py, the team's collector. It reads Claude Code session logs (counts and timestamps only), git history, the board issue, and GitHub issues and PRs.
  • Active time adds up the gaps between logged events, counting at most 10 minutes per gap, so long idle stretches don't count.
  • Brandon's session restarted twice. Each restart copied the earlier conversation into a new log file, with more than 99% overlap. Only the newest log and one helper-agent log were counted; adding all three would have roughly doubled his numbers.
  • Snapshot times differ: Alex's chat figures are from 21:53 UTC; Brandon's chat, git, board and PR figures are from 22:32 UTC.
  • Estimates left out: the problem-solving logs include the agents' own "time saved" estimates. They aren't measurements, so this report doesn't use them.
  • Line counts include generated notebook files with embedded images, so they overstate hand-written code. Code and docs alone: Alex 4,070 lines, Brandon 1,361.
  • Open item: the five-level arm mode passed its self-checks and dry runs against live OD, but hasn't yet moved the real arm.
